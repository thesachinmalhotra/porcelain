# UI Slices B-E: interaction, inspector, commands, and deep-work contexts

## Intent

Slices B-E turn the Slice A canvas-first shell into a coherent authoring environment without creating a second pipeline/runtime/configuration system.

The product boundary remains:

- Redpanda Connect owns component semantics, schema, validation, execution, runtime state and tests.
- React Flow owns spatial graph interaction and viewport mechanics.
- Porcelain owns presentation, interaction grammar, command routing, local draft history and contextual surfaces.
- Browser-local state is presentation/session state; the durable pipeline model remains the existing native Connect authoring boundary.

## Slice B - Canvas interaction

Implemented:

- insertion from the live Connect component catalogue
- single and multi-selection
- drag and persisted node positions
- native React Flow connection interaction with existing Connect connection validation
- node contextual toolbar
- canvas and node context menus
- deletion of processors and the optional buffer
- duplication of processors, including multi-selection duplication
- keyboard grammar:
  - Cmd/Ctrl+K command menu
  - Cmd/Ctrl+Z undo
  - Cmd/Ctrl+Shift+Z redo
  - Cmd/Ctrl+D duplicate
  - Delete/Backspace delete
  - Escape clear selection / leave deep-work context
  - [ and ] toggle side panels
  - Cmd/Ctrl+Backslash toggle both panels
- bounded undo/redo history (100 authoring states per pipeline)

Important semantic boundary: node positions are presentation state. Graph edits are translated back into the existing PipelineAuthoring model. React Flow is never treated as the durable pipeline model.

## Slice C - Inspector

The inspector is now contextual rather than a static property drawer.

Modes:

1. Configure
2. Runtime
3. Diagnostics

Configuration views:

- schema-driven fields
- advanced configuration
- native full-stream source

The native inspector:

- reads the existing Connect JSON Schema
- respects required/optional/default/advanced/deprecated/secret semantics
- supports nested object hierarchy
- supports arrays and enums
- supports field search
- exposes per-field dirty markers and reset-to-native-default behaviour
- provides local scalar validation where the native schema exposes bounds
- keeps raw/native configuration available without inventing a second schema

Published configuration is used as the inspector baseline for dirty comparison.

## Slice D - Command system

src/features/pipelines/commands.ts defines the command contract.

The workspace command registry powers:

- Cmd/Ctrl+K
- keyboard shortcuts
- toolbar actions
- context-menu actions
- node actions

Commands are selection-aware. Node/context-menu actions route through the same command runner with an explicit selection override so the action semantics do not fork between mouse and keyboard paths.

## Slice E - Deep-work surfaces

Deep-work contexts are nested inside the Pipeline Workspace rather than being separate routes.

Implemented contexts:

- Mapping
- Validation
- Test
- Diff
- Runtime

### Mapping

Uses the existing native rpk connect blobl execution path. Mapping fixtures remain ephemeral.

### Validation

Uses the existing Connect validation server boundary against the exact native configuration.

### Test

Runs rpk connect test against a temporary native Connect config and test definition. No custom test runner is introduced. The session editor is intentionally ephemeral until native test-file persistence is designed.

### Diff

Compares the current draft with the persisted published revision using the existing pipeline store. The displayed configuration is the native Connect configuration generated by the existing authoring boundary.

### Runtime

Reads existing Streams API runtime state and stats. Porcelain does not fabricate a second runtime or log transport. Streams Mode exposes stream state/uptime and per-stream stats; process logs require an actual configured log source.

## Deliberate non-goals

Still not implemented here:

- animation and transition choreography
- a second graph executor
- custom Bloblang parsing/evaluation
- custom validation semantics
- persistent browser-side history
- native test-file persistence
- a custom process-log ingestion system
- multi-user collaborative editing
- full Slice F micro-polish

Those remain separate decisions so the product does not accumulate hidden parallel systems.

## Research references

Linear's interaction model explicitly treats selection as the starting point for keyboard, command-menu and contextual-menu actions, with Escape clearing selection. Linear also treats contextual menus as a way to expose discoverable keyboard actions. These principles informed the command routing and selection grammar.

Figma's file model separates navigation, sidebars, canvas and contextual properties, which informed the nested inspector/deep-work structure.

React Flow remains the spatial interaction primitive: selection, multi-selection, dragging, connection handling and viewport state are delegated to it rather than reimplemented.

Redpanda Connect's Streams API remains the runtime authority. Its Streams API exposes readiness, stream status/uptime, configuration and per-stream stats, while Connect's native unit-testing command executes tests against configuration files. Porcelain uses those primitives directly.
